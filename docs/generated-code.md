# Generated Code

Generated code is what an application uses this package through. It holds the
`Targets`, the `RPCService` and `RPCClient` types, and the per-transport
`ServiceMaps` for a set of definitions. The generator writes it into the
definitions project, and it is not edited by hand.

The specification is the reference for everything about generating it:

- [Generator](https://github.com/Paymentbox-com/grpc-service-mesh-api/blob/master/docs/generator.md) covers installing and running
  `grpc-service-mesh-gen`, its flags, and the files it writes.
- [Generated Code](https://github.com/Paymentbox-com/grpc-service-mesh-api/blob/master/docs/generated-code.md) covers what is generated for each
  service and how the types and `ServiceMaps` are named.

This page shows the Go output for this library's reference definitions, and
lists the parts of this package that generated code relies on.

## Reference Output

The reference definitions are in `internal/testproto/definitions/`, laid out as
a definitions project. `shop/order.proto` declares `shop.OrderService`, and
`shop/deployment.proto` sets the directory's transport to `mem`, the in-memory
transport the tests use. `just proto-test` runs `grpc-service-mesh-gen` at the
version `gen_version` names in the `justfile`, the same way a consumer runs it,
and writes the output to `internal/testproto/`:

```
internal/testproto/shop/order.pb.go             message code
internal/testproto/shop/deployment.pb.go        message code
internal/testproto/shop/shop.grpcmesh.go        OrderTargets, OrderService, OrderClient
internal/testproto/servicemaps/servicemaps.go   one ServiceMap per transport
```

CI regenerates the output and fails when it differs from what is committed, so
the reference always matches the pinned generator. The tests run against it.

`shop/shop.grpcmesh.go`:

```go
// Code generated by grpc-service-mesh-gen. DO NOT EDIT.
// source: shop/order.proto

package shop

import (
	"context"
	"github.com/Paymentbox-com/grpc-service-mesh-go/grpcmesh"
	"github.com/Paymentbox-com/service-mesh-go/mesh"
)

// OrderTargets holds one Target per rpc method of OrderService.
var OrderTargets = struct {
	Place  mesh.Target
	Placed mesh.Target
}{
	Place: mesh.Target{
		Segments: []string{"shop", "OrderService", "Place"},
		Kind:     mesh.KindRoute,
		Metadata: map[string]string{
			"deployment_group": "shop",
			"transport":        "mem",
		},
	},
	Placed: mesh.Target{
		Segments: []string{"shop", "OrderService", "Placed"},
		Kind:     mesh.KindTopic,
		Metadata: map[string]string{
			"deployment_group": "shop",
			"transport":        "mem",
			"consumer_group":   "audit",
		},
	},
}

// OrderService is the RPCService for OrderService. A nil field is not
// served.
type OrderService struct {
	Place  func(context.Context, *Order) (*Order, error)
	Placed func(context.Context, *Order) error
}

// Endpoints returns the Endpoints of the ROUTE methods that are set.
func (s OrderService) Endpoints() []mesh.Endpoint {
	var out []mesh.Endpoint
	if s.Place != nil {
		out = append(out, grpcmesh.NewEndpoint(OrderTargets.Place, s.Place))
	}
	return out
}

// Subscribers returns the Subscribers of the TOPIC methods that are set.
func (s OrderService) Subscribers() []mesh.Subscriber {
	var out []mesh.Subscriber
	if s.Placed != nil {
		out = append(out, grpcmesh.NewSubscriber(OrderTargets.Placed, s.Placed))
	}
	return out
}

type orderClient struct{}

// OrderClient calls OrderService through grpcmesh.DefaultTransportRouter.
var OrderClient orderClient

// Place calls the ROUTE method Place.
func (orderClient) Place(ctx context.Context, req *Order, md map[string]string) (*Order, map[string]string, error) {
	return grpcmesh.Call[*Order, *Order](ctx, OrderTargets.Place, req, md)
}

// Placed publishes to the TOPIC method Placed.
func (orderClient) Placed(ctx context.Context, req *Order, md map[string]string) error {
	return grpcmesh.Publish(ctx, OrderTargets.Placed, req, md)
}
```

## What Generated Code Relies On

The generated code calls four generic functions in this package. They are
exported because generated code lives in another package, and they are an
implementation detail between the generator and this package. Applications do
not call them. They are listed here so it is clear what the generator relies
on.

| Function | Called by | What it does |
|---|---|---|
| `NewEndpoint[Req, Resp](target, fn)` | an `RPCService`'s `Endpoints()` | Builds the `mesh.Endpoint` that decodes the request, calls `fn`, and encodes the reply, as described under [Handlers](handlers.md). |
| `NewSubscriber[Req](target, fn)` | an `RPCService`'s `Subscribers()` | Builds the `mesh.Subscriber` that decodes the message and calls `fn`. |
| `Call[Req, Resp](ctx, target, req, md)` | a `ROUTE` method of an `RPCClient` | Sends the request and decodes the reply, as described under [Calling](calling.md). |
| `Publish[Req](ctx, target, req, md)` | a `TOPIC` method of an `RPCClient` | Publishes the message. |

The type parameters are pointer types to generated messages. The package
obtains a fresh message for decoding from the type's zero value through
`zero.ProtoReflect().New().Interface()`, which works on a nil pointer to a
generated type and on nothing else.

A generated `RPCService` type implements the `RPCService` interface, whose
`Endpoints()` and `Subscribers()` methods are what `Register` reads.
